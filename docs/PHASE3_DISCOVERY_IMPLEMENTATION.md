# Phase 3 — Deterministic AI Discovery

[English](#english) · [Español](#español)

Status: **active implementation — first detector: AI Engine 3.7.7**  
Last reviewed / Última revisión: **9 September 2026 / 9 de septiembre de 2026**

---

## English

### Goal

Phase 3 discovers only AI integrations for which the plugin can produce explainable, reproducible WordPress evidence.

Discovery is intentionally conservative. It does not guess whether arbitrary content was generated by AI and it does not classify legal obligations.

### First supported detector

The first validated integration is:

```text
AI Engine
WordPress.org slug: ai-engine
main plugin file: ai-engine/ai-engine.php
text domain: ai-engine
validated version: 3.7.7
active plugin required: yes
```

The 3.7.7 boundary was selected and verified against the current WordPress.org release published on 8 September 2026.

A different installed AI Engine version may still be identified as AI Engine, but it is reported as **outside the validated detector boundary** and cannot be accepted through automated discovery until that version is explicitly validated.

### Evidence contract

The detector observes only WordPress plugin inventory evidence:

```text
plugin basename
plugin name
plugin version
plugin text domain
WordPress active state
```

It does **not** read:

```text
provider credentials
API keys
provider/model configuration
chatbot configuration
prompts
conversations
content
customer data
AI Engine internal options
```

### Deterministic result

A supported result contains:

```text
detector id
integration slug/name
observed version
validated version boundary
plugin inventory evidence
evidence signature (SHA-256)
supported / outside-boundary state
```

The signature is generated from the stable evidence shape. Re-running the detector against the same observation produces the same signature.

### Server-authoritative acceptance

Discovery never writes to the registry automatically.

The administrator flow is:

```text
Tools → AI Discovery
→ observe active WordPress plugins
→ deterministic detector result
→ review evidence
→ explicit Add to registry
→ server re-runs discovery
→ nonce + manage_options
→ supported result only
→ local AI Systems Registry
→ source_origin = discovered
→ review_status = pending
```

No plugin/version/signature value sent by the browser is trusted as discovery authority. The server re-observes WordPress immediately before persistence.

### Candidate semantics

The first AI Engine candidate intentionally uses:

```text
name: AI Engine
type: other
source origin: discovered
review status: pending
interaction context: empty
interaction disclosure required: false
```

The detector does not infer whether AI Engine is being used as a chatbot, content generator, MCP server, assistant or another workflow. Those facts require administrator review or later integration-specific evidence.

### Runtime acceptance

Phase 3 first-detector acceptance must install the exact AI Engine 3.7.7 WordPress.org package in the real `wp-env` single-site runtime and prove:

```text
AI Engine 3.7.7 active
→ discovery page reports supported result
→ exact plugin file/version evidence visible
→ 64-character SHA-256 signature visible
→ responsive + serious/critical axe gate green
→ explicit Add to registry succeeds
→ resulting registry record is Other + Pending review + Active
→ Editor cannot access discovery admin surface
```

All existing Phase 2 regression gates remain blocking.

### Phase 3 boundary

The first increment does not yet claim Phase 3 complete. Phase 3 exit still requires the first supported detector to be merged and verified on `main`, with documentation synchronized and blockers zero.

## Español

### Objetivo

La Fase 3 descubre únicamente integraciones de IA para las que el plugin puede producir evidencia WordPress explicable y reproducible.

El descubrimiento es deliberadamente conservador. No intenta adivinar si un contenido arbitrario fue generado por IA ni clasifica obligaciones legales.

### Primer detector compatible

La primera integración validada es:

```text
AI Engine
slug WordPress.org: ai-engine
archivo principal: ai-engine/ai-engine.php
text domain: ai-engine
versión validada: 3.7.7
plugin activo requerido: sí
```

La frontera 3.7.7 se seleccionó y verificó contra la versión actual de WordPress.org publicada el 8 de septiembre de 2026.

Otra versión instalada de AI Engine puede identificarse como AI Engine, pero se mostrará como **fuera del alcance validado del detector** y no podrá aceptarse mediante discovery automático hasta que esa versión sea validada explícitamente.

### Contrato de evidencia

El detector observa únicamente evidencia del inventario de plugins WordPress:

```text
basename del plugin
nombre del plugin
versión
text domain
estado activo en WordPress
```

No lee:

```text
credenciales de proveedor
API keys
configuración de proveedor/modelo
configuración de chatbots
prompts
conversaciones
contenido
datos de clientes
opciones internas de AI Engine
```

### Resultado determinista

Un resultado compatible contiene:

```text
id del detector
slug/nombre de integración
versión observada
frontera de versión validada
evidencia del inventario
firma de evidencia SHA-256
estado compatible / fuera de alcance
```

La firma se genera desde una estructura estable de evidencia. La misma observación produce la misma firma al volver a ejecutar el detector.

### Aceptación server-authoritative

Discovery nunca escribe automáticamente en el registro.

El flujo del administrador es:

```text
Herramientas → AI Discovery
→ observar plugins WordPress activos
→ resultado determinista
→ revisar evidencia
→ acción explícita Añadir al registro
→ el servidor vuelve a ejecutar discovery
→ nonce + manage_options
→ solo resultado compatible
→ registro local de sistemas de IA
→ source_origin = discovered
→ review_status = pending
```

Ningún valor de plugin, versión o firma enviado por el navegador se utiliza como autoridad del discovery. El servidor vuelve a observar WordPress justo antes de guardar.

### Semántica del candidato

El primer candidato de AI Engine usa deliberadamente:

```text
nombre: AI Engine
tipo: other
origen: discovered
estado de revisión: pending
contexto de interacción: vacío
aviso de interacción requerido: false
```

El detector no infiere si AI Engine se utiliza como chatbot, generador de contenido, servidor MCP, asistente u otro flujo. Esos hechos necesitan revisión del administrador o futura evidencia específica de la integración.

### Aceptación runtime

La aceptación del primer detector debe instalar el package exacto de AI Engine 3.7.7 de WordPress.org en el runtime real single-site de `wp-env` y demostrar:

```text
AI Engine 3.7.7 activo
→ pantalla Discovery muestra resultado compatible
→ evidencia de archivo/versión exacta visible
→ firma SHA-256 de 64 caracteres visible
→ responsive + axe serious/critical verde
→ Añadir al registro explícito funciona
→ registro resultante Other + Pending review + Active
→ Editor no puede acceder a Discovery
```

Todos los gates de regresión de Fase 2 siguen siendo bloqueantes.

### Límite de Fase 3

Este primer incremento todavía no declara la Fase 3 completada. El cierre requiere que el primer detector compatible sea fusionado y verificado en `main`, con documentación sincronizada y blockers en cero.
