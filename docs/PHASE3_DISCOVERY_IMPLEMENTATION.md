## English

### Goal

Phase 3 discovers only AI integrations for which the plugin can produce explainable, reproducible WordPress evidence.

Discovery is intentionally conservative. It does not guess whether arbitrary content was generated by AI and it does not classify legal obligations.

### Accepted detector

```text
AI Engine
WordPress.org slug: ai-engine
main plugin file: ai-engine/ai-engine.php
text domain: ai-engine
validated version: 3.7.7
active plugin required: yes
```

A different installed AI Engine version may still be identified as AI Engine, but it is reported as **outside the validated detector boundary** and cannot be accepted through automated discovery until that version is explicitly validated.

### Evidence contract

The detector observes only:

```text
plugin basename
plugin name
plugin version
plugin text domain
WordPress active state
```

It does not read provider credentials, API keys, model/provider configuration, chatbot configuration, prompts, conversations, site content, customer data or AI Engine internal options.

A supported result contains:

```text
detector id
integration slug/name
observed version
validated version boundary
plugin inventory evidence
stable SHA-256 evidence signature
supported / outside-boundary state
```

### Server-authoritative acceptance

```text
Tools → AI Discovery
→ observe active WordPress plugins
→ deterministic detector result
→ administrator reviews evidence
→ explicit Add to registry
→ server re-runs discovery
→ nonce + manage_options
→ supported result only
→ local AI Systems Registry
→ source_origin = discovered
→ review_status = pending
```

Browser-supplied plugin/version/signature values are never trusted as discovery authority.

### Candidate semantics

The accepted AI Engine candidate intentionally uses:

```text
name: AI Engine
type: other
source origin: discovered
review status: pending
interaction context: empty
interaction disclosure required: false
```

Plugin presence is not treated as evidence that AI Engine is configured as a chatbot, content generator, MCP server or any other specific workflow.

## Español

### Objetivo

La Fase 3 descubre únicamente integraciones de IA para las que el plugin puede producir evidencia WordPress explicable y reproducible.

Discovery es deliberadamente conservador: no intenta adivinar si un contenido fue generado por IA ni clasifica obligaciones legales.

### Detector aceptado

```text
AI Engine
slug WordPress.org: ai-engine
archivo principal: ai-engine/ai-engine.php
text domain: ai-engine
versión validada: 3.7.7
plugin activo requerido: sí
```

Otra versión instalada puede identificarse como AI Engine, pero se muestra **fuera de la frontera validada** y no puede añadirse mediante discovery hasta ser validada explícitamente.

### Contrato de evidencia

El detector observa únicamente:

```text
basename del plugin
nombre
versión
text domain
estado activo en WordPress
```

No lee credenciales, API keys, configuración de proveedor/modelo, configuración de chatbot, prompts, conversaciones, contenido, datos de clientes ni opciones internas de AI Engine.

### Aceptación server-authoritative

```text
Herramientas → AI Discovery
→ observar plugins activos
→ resultado determinista
→ revisión del administrador
→ Añadir al registro explícito
→ el servidor vuelve a observar WordPress
→ nonce + manage_options
→ solo resultado compatible
→ registro local
→ source_origin = discovered
→ review_status = pending
```

Los datos enviados por el navegador nunca son autoridad para la detección.

### Semántica del candidato

```text
nombre: AI Engine
tipo: other
origen: discovered
estado de revisión: pending
contexto de interacción: vacío
aviso de interacción requerido: false
```

La presencia del plugin no se interpreta como prueba de que exista un chatbot u otro flujo concreto.

### Salida de Fase 3

**Completa.** La Fase 4 queda desbloqueada.
