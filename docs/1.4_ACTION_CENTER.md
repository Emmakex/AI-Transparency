# Kairoseth AI Transparency 1.4 — System Action Center

Status: development branch only

## Goal

Turn the v1.3 operational dashboard into a per-system action center. The plugin should not only report state; it should tell an administrator what concrete action remains for each registered AI system and route directly to the correct local workflow.

## Product contract

For every registered AI system, derive a deterministic list of next actions from existing local state only. Actions are navigation/workflow guidance, not legal conclusions and not automated compliance decisions.

Initial action types:

1. Complete administrator context when provider, model/model family, purpose, audience, human oversight or data-use context is missing.
2. Review a pending Registry record.
3. Resolve current deterministic Readiness findings.
4. Review disclosure eligibility once the record is reviewed and active.
5. Open/copy the public disclosure workflow for eligible systems.
6. Generate a fresh Evidence Export after meaningful local state changes.

## UX direction

- Dashboard adds an Action Center section ordered by urgency and system.
- Each action names the affected system, explains why the action exists, and provides one direct CTA.
- Completed/no-action systems remain visible as healthy state without creating noise.
- Counts in the dashboard remain derived from the same Registry/Readiness/Disclosure engines used elsewhere.
- No duplicated persistence layer for action state; action state is derived from authoritative local data.

## Engineering constraints

- Preserve Registry schema v2 unless a real new persisted field is required.
- Do not infer administrator declarations from plugin identity or Discovery evidence.
- Preserve Fact / Administrator declaration / Guidance separation.
- Preserve local-first privacy and site-local Multisite isolation.
- EN/ES customer-facing coverage must remain 100% at merge time.
- All actions require real WordPress browser acceptance, responsive checks and serious/critical accessibility acceptance.
- Evidence Export identity changes only when exported authoritative state changes; dashboard-only action guidance must not alter snapshot signatures.

## First implementation slice

Create a deterministic `SystemActionEngine` (or equivalent domain service) that consumes Registry systems plus current Readiness/Disclosure state and returns bounded action DTOs. Render those actions in the dashboard without adding persistence. Add unit tests for ordering/rules before wiring browser UX.
